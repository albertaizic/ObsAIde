# ObsAIde

An AI assistant built into Obsidian. **Aide** lives in the right sidebar, understands the note or selection you point it at, and can propose edits you review before anything is written.

ObsAIde talks directly to the provider you choose — OpenRouter, OpenAI, Anthropic, Google Gemini, Groq, Mistral, or any OpenAI-compatible endpoint including a local server. There is no ObsAIde backend, no account and no telemetry.

> Status: `0.1.0`, first release. The plugin ID is `obsaide` and is stable.

---

## Features

- **Aide sidebar** — a real chat panel with Markdown rendering, streaming replies, code-block copy buttons, stop/regenerate, and local conversation history.
- **Ask Aide** — highlight a paragraph, run one command, type a question. The selection becomes the context and the answer opens in the sidebar.
- **Note actions** — Explain, Summarise, Teach me, Improve writing, Rewrite, Shorten, Expand. Available from the command palette and the editor context menu.
- **Safe editing** — actions that rewrite Markdown never touch the note. You get a diff, and you choose: replace, insert below, insert at cursor, copy, or cancel.
- **Tutor mode** — switches Aide from "give me the answer" to "help me understand it", with intuition, worked examples and a comprehension check.
- **Explicit context** — nothing from your vault is sent unless you attach it. Attachments are listed in the composer before you press send.
- **Seven providers, one interface** — switch provider or model without changing anything else. Model lists are discovered from the provider where possible.

## Supported providers

| Provider | API | Model discovery | Notes |
| --- | --- | --- | --- |
| OpenRouter | Chat Completions | Yes | Hundreds of models; the picker shows context length and price |
| OpenAI | Chat Completions | Yes | Sends `max_completion_tokens`; omits `temperature` for reasoning models that reject it |
| Anthropic | Messages | Yes | Sends `anthropic-version` and the direct-browser-access header |
| Google Gemini | Generative Language | Yes | Key sent as `x-goog-api-key`, never in the URL |
| Groq | Chat Completions | Yes | |
| Mistral | Chat Completions | Yes | |
| Custom | Chat Completions | If the endpoint exposes `/models` | Any OpenAI-compatible server, including local ones |

Every provider supports streaming. If the environment refuses a streaming request, ObsAIde falls back to a single buffered response instead of failing.

## Install

### From a release

1. Download `main.js`, `manifest.json` and `styles.css` from the release.
2. Put them in `<vault>/.obsidian/plugins/obsaide/`.
3. Reload Obsidian and enable **ObsAIde** under **Settings → Community plugins**.

### From source

```bash
git clone <this-repo> obsaide
cd obsaide
npm install
npm run build
```

Copy `main.js`, `manifest.json` and `styles.css` into `<vault>/.obsidian/plugins/obsaide/`, or clone straight into that folder and run `npm run dev` for a watching build.

## Setup

1. Open **Settings → ObsAIde**.
2. Expand the provider you want and paste an API key. Keys are stored in this plugin's local `data.json` and are only ever sent to the provider they belong to.
3. Select **Choose model**. ObsAIde asks the provider for its model list; you can also type a model ID by hand.
4. Select **Test** to send one very small request that checks the key, the endpoint and the model.

Where to get a key: [OpenRouter](https://openrouter.ai/keys) · [OpenAI](https://platform.openai.com/api-keys) · [Anthropic](https://console.anthropic.com/settings/keys) · [Google AI Studio](https://aistudio.google.com/apikey) · [Groq](https://console.groq.com/keys) · [Mistral](https://console.mistral.ai/api-keys)

For a local model server, use the **Custom** provider: set the base URL (for example `http://localhost:11434/v1`), leave the key empty if it does not need one, and enter the model ID.

## Using Aide

### The sidebar

Select the ribbon icon or run **Open Aide**. The header shows the current provider and model — select either to change it, and the choice is remembered. The overflow menu holds new conversation, recent conversations, tutor mode, and clearing or deleting the current conversation.

Enter sends, Shift+Enter adds a line. While a reply is generating the send button becomes stop.

### Ask Aide

Select some text and run **Ask Aide** (command palette, or right-click → **Ask Aide about this**). A modal opens showing exactly what will be sent, with the selection preview expandable. Type your question and send: the sidebar opens and the answer streams in.

With no selection, the current note is offered instead. With no note open, the modal opens with no context at all.

### Note actions

| Action | Rewrites the note? |
| --- | --- |
| Explain | No |
| Summarise | No |
| Teach me | No |
| Improve writing | Yes |
| Rewrite (your instruction) | Yes |
| Shorten | Yes |
| Expand | Yes |

Actions run on the selection, or on the whole note when nothing is selected. They stream into the sidebar like any other reply.

### Applying an edit

Rewriting actions attach a **Review change…** button to the reply. It opens a modal with a line diff and a plain result view, and offers:

- **Replace selection** / **Replace note content**
- **Insert below**
- **Insert at cursor**
- **Copy**
- **Cancel**

Nothing is written until you press one of those. Changes go through Obsidian's editor API, so Ctrl/Cmd+Z undoes them in one step.

If the note changed after the reply was generated, ObsAIde says so. It looks the original text up once by content; if it is gone or ambiguous, the replace options disappear and only insert and copy remain. It will not overwrite text it cannot verify.

## Note context

Context is always something you attached:

- **Current selection** — snapshotted when you attach it
- **Current note** — read from the vault at send time, so it is never stale
- **Any note** — chosen through a fuzzy picker
- **Nothing** — the default

Attachments appear as removable chips in the composer and stay until you remove them, so the same note can carry across several turns. Each request shows the same chips in the transcript, so you can always see what a given message was sent with.

Long notes are truncated to a per-note and a per-request character budget (configurable), and the model is told the material was truncated.

ObsAIde does not index the vault, does not scan it in the background, and never sends a note you did not attach.

## Privacy

- Requests go **directly** from Obsidian to the provider you selected. There is no ObsAIde server.
- Only the context you attached is included, plus your message and your custom instructions.
- **No telemetry, no analytics, no tracking, no remote code.** The only network requests the plugin makes are the provider calls described above and the provider's model listing.
- API keys are stored in `<vault>/.obsidian/plugins/obsaide/data.json`, are never logged, and are scrubbed from every error message before it is displayed.
- Conversations are stored in `<vault>/.obsidian/plugins/obsaide/conversations.json`. You can turn that off, and delete the history, in settings.
- ObsAIde makes **no claim** about what a provider does with your data. Read the policy of whichever provider you configure. If your notes are sensitive, that is the thing to check.

## Commands

| Command | What it does |
| --- | --- |
| Open Aide | Opens or focuses the sidebar |
| Ask Aide | Ask about the selection, or the current note |
| Explain with Aide | Explain the selection or note |
| Summarise with Aide | Concise summary |
| Teach me with Aide | Tutor-style walkthrough |
| Improve writing with Aide | Clarity and structure, same meaning |
| Rewrite with Aide | Rewrite to your instruction |
| Shorten with Aide | More concise |
| Expand with Aide | Develop further |

The editor context menu adds **Ask Aide about this** and **Aide actions…**.

## Development

```bash
npm install
npm run dev     # watching build
npm run build   # type-check and production bundle
npm run lint    # eslint, including the Obsidian plugin rules
npm test        # vitest
```

Tests never touch the network: the transport is an interface and every provider test uses a fake.

### Architecture

```
src/
  main.ts                 plugin lifecycle and registration only
  commands.ts             command palette and editor menu

  providers/              everything provider-specific
    types.ts              the shared vocabulary (messages, requests, stream events)
    catalog.ts            static description of each provider
    registry.ts           settings + provider id -> adapter
    client.ts             streaming, fallback, error classification
    http.ts               transport interface
    obsidian-http.ts      requestUrl + fetch implementation
    openai-compatible.ts  OpenAI / OpenRouter / Groq / Mistral / custom
    anthropic.ts  gemini.ts  openrouter.ts
    service.ts            settings-aware facade used by the rest of the plugin

  chat/                   conversation model, local store, controller
  context/                attachment capture, resolution and formatting
  actions/                note action registry, runner, safe apply
  prompts/                every prompt string lives here
  settings/               settings schema, validation, settings tab
  ui/                     views and modals
  utils/                  ids, text, diff, secret redaction
```

Adding a provider means writing one adapter and one catalogue entry. Adding a note action means adding one entry to `src/actions/registry.ts`.

## Known limitations

- **Text only.** No image input, no tool use, no function calling.
- **No vault-wide search.** Aide sees the notes you attach and nothing else — by design, but it means it cannot answer "which of my notes mentions X".
- **Streaming depends on the environment.** Where the renderer blocks a cross-origin streaming request, ObsAIde silently uses a buffered request instead; the reply then arrives all at once.
- **Replacing text requires the note to be open.** The review modal can only apply a change to a note that is open in a Markdown editor.
- **Model lists are the provider's.** If a provider's listing includes models that cannot chat, they will appear in the picker.
- **Conversations are per-device.** There is no sync beyond whatever syncs your `.obsidian` folder.
