# ObsAIde

An AI assistant built into Obsidian. **Aide** lives in the right sidebar, understands the note, selection or folder you point it at, and writes back into your notes only when you tell it to.

ObsAIde talks directly to the provider you choose — OpenRouter, OpenAI, Anthropic, Google Gemini, Groq, Mistral, or any OpenAI-compatible endpoint including a local server. There is no ObsAIde backend, no account and no telemetry.

> Status: `0.1.0`. The plugin ID is `obsaide` and is stable.

---

## Features

- **Aide sidebar** — a real chat panel: streaming replies, rendered Markdown, code-block copy buttons, stop and regenerate, selectable text, and local conversation history.
- **Ask Aide** — highlight a paragraph, run one command, ask a question. The selection is the subject and the note it came from travels with it, so "why is *this* O(log n)?" still knows what *this* is.
- **Note actions** — Explain, Summarise, Teach me, Improve writing, Rewrite, Shorten, Expand, from the command palette or the editor context menu.
- **Attach notes and folders** — attach any Markdown note, several notes, or a whole folder (recursively). Non-Markdown files are never involved.
- **Write back safely** — every reply can be copied or inserted at the cursor it was asked from. Rewriting actions show a diff first. Nothing is written without a click.
- **Tutor mode** — switches Aide from "give me the answer" to "help me understand it".
- **Concise by default** — answers lead with the answer. Ask for note content and you get the content, not "Sure! Here's a paragraph you could add:".
- **Explicit context** — nothing from your vault is sent unless you attach it, and the composer shows exactly what will go.

## Supported providers

| Provider | API | Model discovery | Notable specifics |
| --- | --- | --- | --- |
| OpenRouter | Chat Completions | Yes | Picker shows context length and per-million price |
| OpenAI | Chat Completions | Yes | Sends `max_completion_tokens`; omits `temperature` for reasoning families |
| Anthropic | Messages | Yes | Sends `anthropic-version` and the direct-browser-access header |
| Google Gemini | Generative Language | Yes | Key sent as `x-goog-api-key`, never in the URL |
| Groq | Chat Completions | Yes | |
| Mistral | Chat Completions | Yes | Temperature clamped to the documented ceiling of 1.0 |
| Custom | Chat Completions | If the endpoint exposes `/models` | Any OpenAI-compatible server, including local ones |

Every provider supports streaming. If the environment refuses a streaming request, ObsAIde falls back to a single buffered response rather than failing.

## Install

### From a release

1. Download `main.js`, `manifest.json` and `styles.css` from the release.
2. Put them in `<vault>/.obsidian/plugins/obsaide/`.
3. Reload Obsidian and enable **ObsAIde** under **Settings → Community plugins**.

### From source

```bash
git clone <this-repo> obsaide
cd obsaide
npm install
npm run build
```

Copy `main.js`, `manifest.json` and `styles.css` into `<vault>/.obsidian/plugins/obsaide/`, or clone straight into that folder and run `npm run dev` for a watching build.

## Setup

1. Open **Settings → ObsAIde**.
2. Expand the provider you want and paste an API key. Keys are stored in this plugin's local `data.json` and are only ever sent to the provider they belong to.
3. Select **Choose model**. ObsAIde asks the provider for its model list; you can also type a model ID by hand.
4. Select **Test** to send one very small request that checks the key, the endpoint and the model.

Where to get a key: [OpenRouter](https://openrouter.ai/keys) · [OpenAI](https://platform.openai.com/api-keys) · [Anthropic](https://console.anthropic.com/settings/keys) · [Google AI Studio](https://aistudio.google.com/apikey) · [Groq](https://console.groq.com/keys) · [Mistral](https://console.mistral.ai/api-keys)

For a local model server, use the **Custom** provider: set the base URL (for example `http://localhost:11434/v1`), leave the key empty if it does not need one, and enter the model ID.

## Using Aide

### The sidebar

Select the ribbon icon or run **Open Aide**. The header shows the current provider and model — select either to change it, and the choice is remembered per provider. The overflow menu holds new conversation, recent conversations, tutor mode, and clearing or deleting the current conversation.

Enter sends, Shift+Enter adds a line. You can keep typing while a reply streams; the send button becomes stop.

The transcript stays pinned to the newest message while you are reading along, and stops following the moment you scroll up. A **jump to latest** button appears while you are scrolled back.

Message text is selectable: drag across a sentence, a paragraph or part of a code block and copy it like anywhere else.

### Ask Aide

Select some text and run **Ask Aide** (command palette, or right-click → **Ask Aide about this**). A modal opens listing exactly what will be sent:

```
Selection — primary
Test.md — context
```

The selection is what you are asking about; the note it came from is background, so a sentence like "Its time complexity is O(log n)" is still understood as being about binary search. Either chip can be removed before sending, and you can add further notes or folders. With no selection, the current note is the subject on its own.

### Note actions

| Action | Rewrites the note? |
| --- | --- |
| Explain | No |
| Summarise | No |
| Teach me | No |
| Improve writing | Yes |
| Rewrite (your instruction) | Yes |
| Shorten | Yes |
| Expand | Yes |

Actions run on the selection, or on the whole note when nothing is selected, and stream into the sidebar like any other reply.

### Getting a reply into a note

Every assistant reply carries compact actions:

- **Copy**
- **Insert at cursor** — writes at the caret in the note the request was made from
- **Use in note…** — opens the review modal with every option

Rewriting actions additionally show a **Review change…** button with a line diff and:

- **Replace selection** / **Replace note content**
- **Insert below**
- **Insert at cursor**
- **Copy**
- **Cancel**

The target note is decided when you *ask*, not when you click. ObsAIde records the note, the caret and the selection at that moment, so opening the sidebar and a modal — both of which take focus — cannot make a reply land somewhere else. Changes go through Obsidian's editor API, so Ctrl/Cmd+Z undoes them in one step.

If the note changed in the meantime, ObsAIde says so and looks the original text up once by content. If it is gone or ambiguous, the replace options disappear and only insert and copy remain. If the note is no longer open at all, insertion is hidden entirely rather than writing to whatever happens to be in front of you.

## Note context

Context is always something you attached:

| Source | Behaviour |
| --- | --- |
| **Current selection** | Snapshotted when you attach it |
| **Current note** | Read from the vault at send time, so it is never stale |
| **Any note** | Chosen through a fuzzy picker over Markdown files |
| **A folder** | Every Markdown note inside it, at any depth |
| **Nothing** | The default |

Attachments appear as removable chips and stay until you remove them, so the same material can carry across several turns. The transcript shows the same chips on each message, so you can always see what a given request was sent with.

### Folders

Attaching a folder collects its Markdown notes recursively:

```
CSE/
├── Algorithms.md          ← attached
├── Week 1/
│   ├── Searching.md       ← attached
│   └── Sorting.md         ← attached
└── Week 2/
    ├── Graphs.md          ← attached
    └── graph.png          ← ignored
```

The chip reads `CSE — 4 notes`; select it to list exactly which notes are included. Notes are ordered by path, so the same folder always produces the same context.

Only `.md` files are ever involved. Images, PDFs and everything else are not "unsupported" — they simply never enter the pipeline, because the vault's Markdown index is the input. They do not appear in pickers, are not decoded, and are never sent.

### Budgets

Every request is bounded by a per-note and a whole-request character budget (both configurable). Notes are trimmed in the order you attached them; once the budget is spent, the remaining notes are listed to the model as omitted rather than silently dropped, and the transcript tells you: *"1 note was shortened and 2 notes were left out to fit the context budget."*

Attaching a large folder cannot bypass this. ObsAIde does not index the vault, does not scan it in the background, and never sends a note you did not attach.

## Answer style

The default persona is a note-taking helper, not an essayist:

- Answers lead with the answer — no preamble, no restating the question, no closing summary.
- Length tracks the question. *"Is Mars red?"* gets a sentence.
- Asking for note content ("write the next paragraph", "add a definition of polymorphism here") returns the content itself, ready to insert.
- **Tutor mode** is the deliberate exception and is free to explain at length.

Add your own standing instructions in settings if you want a different tone or language.

## Privacy

- Requests go **directly** from Obsidian to the provider you selected. There is no ObsAIde server.
- Only the context you attached is included, plus your message and your custom instructions.
- **No telemetry, no analytics, no tracking, no remote code.** The only network requests the plugin makes are the provider calls described above and the provider's model listing.
- API keys are stored in `<vault>/.obsidian/plugins/obsaide/data.json`, are never logged, and are scrubbed from every error message before it is displayed.
- Conversations are stored in `<vault>/.obsidian/plugins/obsaide/conversations.json`. You can turn that off, and delete the history, in settings.
- ObsAIde makes **no claim** about what a provider does with your data. Read the policy of whichever provider you configure. If your notes are sensitive, that is the thing to check.

| Command | What it does |
| --- | --- |
| Open Aide | Opens or focuses the sidebar |
| Ask Aide | Ask about the selection, or the current note |
| Explain with Aide | Explain the selection or note |
| Summarise with Aide | Concise summary |
| Teach me with Aide | Tutor-style walkthrough |
| Improve writing with Aide | Clarity and structure, same meaning |
| Rewrite with Aide | Rewrite to your instruction |
| Shorten with Aide | More concise |
| Expand with Aide | Develop further |

The editor context menu adds **Ask Aide about this** and **Aide actions…**.

## Settings

| Setting | Notes |
| --- | --- |
| Default provider | Also switchable from the sidebar header |
| Custom instructions | Appended to the system prompt on every request |
| Tutor mode by default | New conversations start in tutor mode |
| Stream responses | Falls back to a buffered request where streaming is unavailable |
| Temperature / creativity | `0.0`–`1.0`, default `0.3`. Clamped per provider, and omitted entirely for models that reject it |
| Maximum response length | A cap, not a target: length is governed by the prompt |
| Context budgets | Per-note and per-request character limits |
| Conversation history | Store locally, or turn off and delete |

Temperature is capped at `1.0` on purpose: above that most chat models degrade into incoherent output, and a global slider is the wrong place to do that by accident. A value stored by an earlier version is clamped and rewritten on load, so it cannot keep being sent invisibly.

## Development

```bash
npm install
npm run dev     # watching build
npm run build   # type-check and production bundle
npm run lint    # eslint, including the Obsidian plugin rules
npm test        # vitest
```

Tests never touch the network: the transport is an interface and every provider test uses a fake. Editor and vault logic is written against minimal structural interfaces, so positions, folder collection and context budgets are tested without Obsidian.

### Architecture

```
src/
  main.ts                 plugin lifecycle and registration only
  commands.ts             command palette and editor menu

  providers/              everything provider-specific
    types.ts              the shared vocabulary (messages, requests, stream events)
    catalog.ts            static description of each provider
    capabilities.ts       which sampling parameters a model actually accepts
    registry.ts           settings + provider id -> adapter
    client.ts             streaming, fallback, error classification
    http.ts               transport interface
    obsidian-http.ts      requestUrl + fetch implementation
    openai-compatible.ts  OpenAI / OpenRouter / Groq / Mistral / custom
    anthropic.ts  gemini.ts  openrouter.ts
    service.ts            settings-aware facade used by the rest of the plugin

  chat/                   conversation model, local store, chat controller
  context/                attachment capture, folder collection, formatting
  actions/                note actions, edit anchors, safe apply
  prompts/                all prompt text
  settings/               settings schema, validation and settings tab
  ui/                     views, modals, scroll handling
  utils/                  ids, text, diff, secret redaction
```

Adding a provider means writing one adapter and one catalogue entry. Adding a note action means adding one entry to `src/actions/registry.ts`.

## Known limitations

- **Markdown only, by design.** No images, PDFs, CSVs or provider-native file uploads. ObsAIde attaches Obsidian notes.
- **Text only.** No image input, tool use or function calling.
- **No vault-wide search.** Aide sees what you attach and nothing else, so it cannot answer "which of my notes mentions X" without you attaching the folder.
- **Insertion requires the note to be open.** If the originating note has been closed, insert options are hidden and only copy remains.
- **Streaming depends on the environment.** Where the renderer blocks a cross-origin streaming request, replies arrive all at once.
- **Model lists are the provider's.** A listing that includes non-chat models will show them.
- **Conversations are per-device.** There is no sync beyond whatever syncs your `.obsidian` folder.
